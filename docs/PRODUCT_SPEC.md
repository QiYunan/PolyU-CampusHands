# CampusHands 产品规格

## 用户与问题

CampusHands 面向 PolyU 学生。学生在校园内临时需要物品或帮助时，公开社交帖子常因曝光不稳定、响应慢、地点不相关而难以在截止时间前完成求助。产品以校内、地点和时限为约束，帮助求助者联系可用的同学并跟踪交接结果。

首个场景从 **BorrowLoop** 扩展为物品与服务两类校园求助。已知物品仍可归类为科学计算器、充电器、转接头、文具和雨伞；任意新物品使用 `other` 兜底，搬运器材、现场协助等需求使用 `service`，不得被强制映射为科学计算器。图片识别、GPS／实时地图、真实校方认证、外部通知、移动 App 和多校支持不属于当前阶段。第六阶段只用离线地点 registry 校验并标准化 Requester 填写的交接地点，不提供导航，也不根据 Helper 预设位置判断其能否响应。

## 用户能做什么

- **Requester**：描述需求摘要、类型、地点和截止时间；借物时可确认品牌、型号和替代规则；主动发布请求；查看安全的帮助说明或替代提案、公开时间线与认领后的交接信息；取消请求并确认交接完成。
- **Helper**：在登录后的站内求助广场查看所有已发布且仍开放的请求；自行判断能否在截止时间前完成，通过确认弹窗响应、暂不参与或恢复隐藏；认领成功后确认交接完成。预设物品、位置、available 状态和信誉不控制按钮。
- **演示者**：在明确标注的 Demo Mode 中切换 Alice、Erin、Grace 等虚构角色，演示一人发布、多人同时可见、首个有效认领成功的流程。演示数据不使用真实学生资料。

一次完整物品流程：Alice 提出“30分钟之后，在Z栋交接，需要一台Casio计算器”，直接在最终确认表单中核对摘要、地点、紧急程度和偏好后创建请求；Erin 与 Grace 同时看到请求，各自在弹窗中确认能按时完成并填写实际品牌／型号，首个有效直接响应者获得请求。一次完整服务流程：“20分钟后，在Z栋，需要同学帮我搬运实验器材，有偿”必须解析为 `service`，所有 Helper 都可自行确认并响应，不要求物品类型。公开时间线只显示解析确认、发布、成功认领或提案接受与交接事件，不展示未参与者或内部推理。

确定性流程中，自然语言先进入独立草稿；“确认并创建请求”在一个事务内应用页面当前全部字段、重新校验并创建正式请求，不能确认服务器上的旧字段。发布后，开放请求在 Helper 广场持续可见，直到有效认领、Alice 取消或截止时间到达。服务只复核请求开放、未过期、响应者不是 Requester、能力确认和品牌规则；不以预设库存、Helper 位置、available 状态、步行时间或信誉决定资格。`ask_before_substitute` 的不匹配响应先成为 `proposed` Offer，Alice 接受后才唯一匹配；服务和自主声明 Offer 可以没有 `item_id`。成功认领后继续交接，直到双方确认完成或 Requester 取消。

## 阶段范围

**第一阶段仅验证前端 → 后端 → 数据库 → 前端的基础闭环。** 用户通过结构化表单创建一条借物请求，刷新或重新打开页面后仍能读取同一记录。此阶段不接入真实 LLM，也不要求自然语言解析、候选人匹配、Helper Inbox 或 WebSocket。详见 [里程碑 01](milestones/01-mvp-foundation.md)。

后续依次交付确定性的 BorrowLoop 匹配和交接、Agent 与模型接入、实时更新、演示与协作加固；以 [里程碑目录](milestones/02-borrowloop-flow.md)及 [验收场景](ACCEPTANCE_TESTS.md)为阶段边界。最终课程演示需可交互、展示有意义的对话与 Agent 行为，并能在五分钟内可靠完成。

[Milestone 06](milestones/06-matching-quality.md) 补足通用需求摘要、物品／服务类型、主校园地点、品牌／型号偏好和自主响应广场。产品上的广场面向 CampusHands Helper，不是生产级公开互联网服务；Demo 角色切换只是模拟身份，并非真实登录。短时校园拍摄可用随机 Quick Tunnel URL 让不同网络的演示设备访问同一虚构 Demo，但 URL 持有者均可访问，不能输入真实资料，也不改变角色或资源权限。发布后所有 Demo Helper 都看到同一开放请求和可点击的响应按钮，按紧急程度、截止时间、发布时间和稳定 ID 排序。Helper 选择暂不参与只隐藏自己的列表，不影响其他人。默认界面不展示结构化调试入口，也不公开预设库存、位置、availability 或信誉数据。

## 体验原则

- 优先呈现当前状态、下一步可做的动作和截止时间；移动端基本可用。
- 候选人与结果来自实际演示数据；不向用户暗示尚未发生的接受、交接或完成。
- 内部匹配字段不形成公开用户排名。
- 产品文案与技术实现的职责分界见 [架构](ARCHITECTURE.md)和 [Agent 工作流](AGENT_WORKFLOW.md)。
