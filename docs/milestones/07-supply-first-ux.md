# Milestone 07: Supply-first Helper experience

## 目标

把 M06 的公开求助广场替换为产品默认路径中的供给优先流程：Helper 长期保存物品和服务能力，每天只更新愿意帮助、时间、楼栋和今日可提供项；Requester 通过 AI 或手动页面调用同一确定性搜索服务，并只向一至三名候选发送邀请。

M06 广场接口暂时保留用于旧客户端和回归测试，但 M07 页面不展示或调用该入口。详细字段以 [M07 API 契约](../M07_API_CONTRACT.md)为准。

## 范围

- 长期物品与受控服务能力资料，支持软停用和历史引用。
- 香港本地日期的每日状态；未保存今日状态时只建议沿用上次清单，不自动开启。
- 物品与服务的确定性硬筛选、稳定排序和隐私安全候选结果。
- 每轮一至三人的定向邀请；Requester 可关闭当前轮次并在同一请求上重新搜索。
- 第一位有效接受者原子成功，其他邀请关闭；替代物品继续受 Requester 同意控制。
- Helper 的“我的今日状态”和“收到的邀请”独立前端组件。
- 邀请 WebSocket 只发送失效通知，HTTP GET 仍是权威快照，断线后每两秒轮询。

不在本阶段实现 GPS、实时地图、课程表、外部推送、生产认证、多实例消息总线或真实学生资料。

## 硬性匹配规则

候选必须开启今日愿意帮助，时间覆盖请求截止，今日能力匹配，能够按静态校园步行估算加三分钟缓冲到达，不是 Requester，没有 `matched`／`in_progress` 任务，没有拒绝或表示无法到达该请求。紧急请求还要求 Helper 接受紧急请求。

排序依次使用匹配等级、预计到达、时间余量、内部信誉、近七天承担任务数和 Helper ID。API 只公开显示名、匹配理由、预计到达时间、可帮助时间和 A/B/C/New 信誉等级。

## 验收边界

自动化必须覆盖旧库幂等迁移、资料与每日状态权限、物品和服务搜索、隐私、关闭并重开邀请轮次、替代物品及并发接受。最终验收仍需 Alice、Erin、Grace 在三台实体设备上完成定向邀请闭环，并分别验证课堂 LAN/热点与临时 Quick Tunnel；单机多浏览器不等同于实体设备验收。
